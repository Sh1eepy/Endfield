# 终末地混合 GraphRAG 架构、构建流程与质量门禁

> 版本：v2，2026-08-20。本文描述当前已经落地的实现，不把规划项写成已完成功能。
> RAG/图谱统一协作、LLM 调用矩阵和长文档审计以根目录 `KNOWLEDGE_SYSTEM_ARCHITECTURE.md` 为准。

## 1. 定义与目标

知识图谱不是 GraphRAG 的同义词。知识图谱负责保存“实体—关系—实体”和证据；GraphRAG 是在
问答时利用图谱定位关系路径，再把路径及原始证据交给 LLM。项目采用混合架构，不用图谱替代所有
RAG：

```text
用户问题
  ├─ 配方/设备/材料精确事实 → recipes.json 结构化直查
  ├─ 人物/组织/地点/任务/物品/设备关系 → SQLite 知识图谱（1-3 跳）
  ├─ 剧情、档案、原因、性格解释 → 向量 + BM25 + mention 原 RAG
  └─ 复合或图谱缺边 → 图定位 + 原文 RAG 取证；无图证据时回退而不猜测
```

核心原则：图谱回答“事实怎样连接”，RAG回答“原文具体说了什么”，LLM只负责基于证据组织表达。

## 2. 当前数据模型

图数据库位于 `output/knowledge_graph/graph.db`，使用 SQLite，避免为约两千条 WIKI 数据引入
Neo4j 服务、账号和部署成本。

### 2.1 表

- `entities`：稳定 ID、标准名称、实体类型、分类、来源条目；
- `aliases`：别名、别名类型、对应实体、证据、审核状态；
- `relations`：主体、谓词、客体、来源条目、证据、置信度、抽取方式、审核状态；
- `manifest`：每个来源条目的 `content_hash` 和本条目产出的关系数量；
- `meta`：schema 版本和构建时间。

### 2.2 已上线关系

| 谓词 | 来源 | 可靠度 |
|---|---|---|
| `HAS_PARTICIPANT` | 任务“相关人物”结构 | 确定性规则 |
| `LOCATED_IN` | 任务“地点”结构 | 确定性规则 |
| `PREVIOUS_QUEST` / `NEXT_QUEST` | 任务前后置表格 | 确定性规则 |
| `AFFILIATED_WITH` | 干员“身份认证”字段 | 确定性规则 |
| `REFERENCES` | `sections_struct` entry 引用 | 确定性规则 |
| `PART_OF` | “武陵城→武陵”一类地点层级 | 受控规则 |
| `REWARDS` / `UNLOCKS` | 任务奖励、解锁内容章节 | 确定性规则 |
| `RECOMMENDS_WEAPON` / `RECOMMENDED_FOR` | 干员/武器推荐章节 | 确定性规则 |
| `REQUIRES_MATERIAL` | 干员精英化章节的结构化物品引用 | 确定性规则 |
| `OBTAINED_FROM` / `USED_FOR` | 物品和设备来源、用途章节 | 确定性规则 |
| `DEVICE_USES_INPUT` / `DEVICE_PRODUCES` | `recipes.json` 345 条配方 | 精确结构化数据 |
| `AUTHORITY` | “地区科学发展区管代/我是地区的管代”明确职称句式 | 受控规则 |

“朋友、喜欢、信任、敌对”等需要语义判断的关系不会自动进入正式图。共同参与任务是查询时
动态计算的两跳路径，不固化成新边，避免派生关系在增量更新时失效或扩散错误。

### 2.3 别名治理

人工审定别名存放在 `scripts/graph_aliases.json`。当前已录入“李织烟→诀”，并保留证据和
`human_verified` 状态。模型抽取的候选别名未来必须进入待审核区，不能覆盖人工结果。

## 3. 构建与增量更新

### 3.1 首次构建

```powershell
python scripts/build_knowledge_graph.py
```

流程：读取 22 类 JSONL → 建立所有 WIKI 条目实体 → 提取高可信结构关系 → 导入配方关系与人工别名 →
清理无引用合成实体 → 写 manifest 和构建报告。

### 3.2 增量构建

```powershell
python scripts/build_knowledge_graph.py --incremental
```

每个来源条目计算 `sha256(name + category + full_text)`：

```text
新增条目 → 建实体、抽关系、写 manifest
修改条目 → 按 source_item_id 删除旧边 → 从新版重新抽取 → 原子提交
删除条目 → 删除该来源拥有的边和 manifest；仍被引用的实体保留
未变化   → 不处理
```

`recipes.json` 是独立且仅 345 条的精确数据，每次构建都删除并重建 `recipe_rule` 边；这比给第二份
manifest 增加复杂度更低，也能保证配方变更不会被 KB 的增量状态遮蔽。

关系的所有权属于 `source_item_id`，因此不会出现“新版删掉人物，旧边却继续残留”。人工审核别名
不会被普通增量过程删除。事实边持久化，派生路径动态计算，减少依赖重算。

## 4. 查询与路由

`scripts/graph_search.py` 负责：

1. 从标准名和别名中抽取全部实体；
2. 识别所属组织、相关人物、地点、前后置、本名等谓词；
3. 单实体问题读取指定关系；
4. 双实体问题执行最多三跳的双向 BFS；
5. 每条路径返回边证据、来源条目、跳数和置信度；
6. `rag_ask.ask()` 对明确关系问题优先调用图谱。

解释性问题（如“诀是不是挺中意管理员”）不走事实边直答，而走 `hybrid_relation`：图谱定位人物与
共同事件，文本层从任务、档案和对话中抽取含人物/管理员的局部证据窗口，最后要求 LLM 分成
“原文明确事实 / 基于证据的合理解读 / 资料不足”。这解决了图谱不适合长剧情、性格与语气概括的
信息损失，同时避免把一次模型判断永久污染图谱。

长档案不会在生成阶段固定截取前 N 字。生成器会在完整来源内按查询实体、关系与各子问语义选择
分散证据窗口，再在字符预算内按原文顺序组合；这使“答案在档案末尾”的实体直取结果仍能进入 LLM。
图谱负责已结构化关系，但不是长文截断问题的替代修补手段。

图谱没有路径时回退原混合 RAG，并标记 `graph_attempted=true`。“没有被图谱收录”不等于
“关系不存在”。不对所有问题强行融合图分数和向量分数；复合问题采用“图定位→原文取证”的串联。

## 5. 错误控制与人工审查

关系错误分为实体识别、实体链接、关系抽取和来源冲突。正式入图要求：

- 主客体类型符合 schema；
- 每条边必须有非空原文/字段证据；
- 保存抽取方式、置信度、来源和审核状态；
- 禁止自循环和未知谓词；
- 结构化规则可自动通过；LLM 推断只能作为候选；
- “共同出现”只生成共同任务路径，不能自动升级为朋友、师徒或上下级；
- 纠错采用 `candidate → verified → rejected/deprecated`，不得无记录覆盖。

未来引入 LLM 关系抽取时，应让抽取器输出原文证据，再用独立验证器判断“支持/部分支持/不支持”；
高风险关系进入人工审核。人工更正必须记录旧值、原因、操作者、时间和图版本。

## 6. 审计、评测与质量门禁

### 6.1 图一致性审计

```powershell
python scripts/graph_audit.py --fail-on-error
python scripts/audit_relation_queries.py --fail-on-error
```

检查：数据库表、外键、谓词白名单、空证据、审核状态、自循环、悬空来源、知识库/manifest key、
条目 hash 新鲜度。结果写入 `output/knowledge_graph/audit_report.json`。

第二个命令从每类真实关系边自动采样，分别生成正向问、反向问和是非问，并检查同一条边在三种
问法下都能返回。它解决了人工逐条试问效率低以及只覆盖一个方向的问题，结果写入
`output/knowledge_graph/relation_query_audit.json`。

### 6.2 关系专项评测

```powershell
python scripts/eval_graph.py
```

`output/eval/graph_eval_set.jsonl` 当前覆盖：所属组织、人工别名、双实体共同任务、任务人物、
任务地点、前置任务、职务关系正反问和配方设备产出。指标是路径召回率，结果写入 `output/eval/graph_result.json`。新增真实关系问题
必须加入该评测集，尤其要补充无证据拒答、同名实体、冲突来源和三跳组织关系。

### 6.3 总质量门禁

```powershell
python scripts/quality_gate.py
```

在原召回、路由、答案引用/拒答门禁上新增：

- 图审计必须 `consistent=true`；
- 图路径召回率必须 ≥ 90%；
- 自动关系问法审查通过率必须 ≥ 98%；
- 任一失败返回非零退出码，现有 CI 的 `quality_gate.py` 步骤会阻止合并。

门禁不等于效果评测。当前 10 条关系集只能证明核心链路可用，不能代表所有剧情关系。上线更多
关系类型前应扩到至少 30-50 条，按单跳、双跳、三跳、别名、冲突、拒答分别报告。

## 7. 当前构建结果与边界

2026-08-20 v2 全量构建：2,129 实体、1 个审定别名、9,358 条关系、1,958 个来源条目；审计零问题。
关系包含 986 条配方输入/产出边，并已对各关系类型批量执行正问、反问和是非问审查。

当前能稳定回答“诀属于哪个组织”“诀的本名”“某任务有哪些人物/发生在哪里/前后置是什么”，以及
“陈千语和诀共同参与过哪些任务”。“武陵的领袖是谁”现由两条明确“管代”原文证据支持庄方宜，
回答应保留“管代/管理负责人”这一原始职称，而不能仅凭该边扩大解释为政治意义上的最高领袖。

## 8. 后续扩展顺序

1. 扩充明确职位句式，并将低置信度候选送人工审核；
2. 建立同名实体消歧与更多本名/代号表；
3. 扩充关系评测集、解释性关系人工评分集和负例；
4. 图路径根据 `source_item_id` 拉取完整原文，形成标准“图定位→RAG取证”；
5. 只有数据规模和运维需求明显增长时再评估 Neo4j，不因概念流行提前增加服务。
