# 后端第一阶段整改结果（2026-09-08）

基线 commit：`4a4ec99bb625340fbdb871b9f8e48016a8923af8`
整改分支：`codex/backend-remediation`

## 已完成

- 实体定位改为最长完整名称，修复“重息壤→息壤”“诀的信物→诀”的错误截断；实体直取来源保留真实 `item_id`。
- RAG 名称规范化和分词改为加载时预计算，向量 chunk ID 映射改为常驻索引；实体命中时不再无条件重复检索，规划器重复子查询会去重。
- 流式 LLM 响应只有明确 `finish_reason=stop` 才视为成功；普通 EOF 或仅 `[DONE]` 且缺少结束原因会进入错误路径，避免半截答案伪装为完成。
- RAG 增量构建按实际 chunk 集合对账，会删除条目缩短或重切分留下的旧向量；embedding 模型变化要求新输出目录；BM25/manifest 原子发布，最终审计失败使命令失败。
- GraphRAG 指纹覆盖结构化章节、干员详情和规则 schema；实体更新使用 UPSERT，避免 `INSERT OR REPLACE` 删除被关系引用的实体；运行时以 SQLite 只读模式打开，单来源路径返回可追溯 `item_id`。
- 媒体代理只接受明确的安全图片/音频 MIME，拒绝 SVG、HTML 和未知媒体，并添加 sandbox CSP；CORS 改为显式来源、方法和请求头白名单。
- `/api/synthesis` 限制名称长度与树深；问答并发已满时不扣频率/每日额度。

## 第二阶段补充

- 同一来源的多个检索 chunk 会合并为一个有界证据块，来源去重不再丢失后续章节。
- 名称通道按来源去重，并把用户明确点名或省略常见后缀的高置信条目保留在最终 Top-K。
- 新的评测 manifest 包含数据集、索引、参数、Prompt 以及检索/路由/评测源码哈希。
- 答案 judge 输入加入生成时实际使用的检索原文；新增 `--require-versioned-results` 发布严格门禁。
- LLM 首次请求、网络退避、重试与截断续写共享 75 秒默认总预算；超限直接进入现有降级路径。

71 条严格检索集实测从修排序前的 Recall@5 `97.18%`、MRR `0.955` 提升为 Recall@5
`100%`、MRR `0.984`。P@5 从 `0.470` 变为 `0.454`，原因是同一相关来源的重复 chunk
不再被重复计数；最终上下文的来源多样性更高。25 条离线路由集 route accuracy 为 `0.92`。

严格发布门禁目前按预期拒绝 `final_reviewed.json` 和 `answer_result.json`：这两份历史结果缺少
manifest 元数据。需要人工复核召回集，并显式运行在线答案评测后，才能将它们升级为新基线。
