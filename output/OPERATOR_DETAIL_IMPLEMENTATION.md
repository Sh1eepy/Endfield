# 干员详情展示实施说明

## 本阶段完成内容

原始 WIKI 干员页面不是单篇文本，而是“章节 → 组件 → Tab → 富文本块/音频”的结构。
旧提取器只读取组件 `default` Tab，导致基本信息、战斗技能、天赋阵列、潜能、明信片、档案、
语音和官方演示大量缺失。本阶段新增 `scripts/build_operator_details.py`，从本地原始 WIKI JSON
生成 `output/operator_details.json`，当前覆盖 31 名干员。

详情库保留：

- 干员基本信息键值对；
- 原始章节、组件与全部 Tab；
- 富文本粗体、斜体和颜色 token；
- 技能数据、升级材料、精英化和天赋表格；
- 图片、动态图、潜能明信片与官方演示图；
- 中/英/日/韩语音标题、台词与真实音频 URL；
- 物品/武器引用的独立实体边界。

## 前端交互设计

页面使用两级局部切换：一级按钮切换“干员资料/能力扩延/潜能/攻略/档案/语音/官方情报”，
二级 Tab 切换同一组件内的技能、天赋、明信片、档案页和语种。切换只更新详情局部区域，带平移、
淡入和轻微模糊恢复动效，并支持 `prefers-reduced-motion`。

基本信息采用“小号灰色字段标签 + 大号深色字段值”，明确区分“阵营”和“终末地工业”等主次。
原始 `light_rank_yellow/orange/blue/...` 与 `light_function_*` token 映射为可读的金、橙、蓝、绿、
紫、红等前端色彩；因此“金色代表主能力”的说明与实际文字颜色保持一致。武器和材料引用使用独立
间隔卡片，避免多个名称黏连。

语音使用页面内播放按钮，同一时间只播放一条；再次点击暂停，播放结束自动恢复按钮状态。

## 数据与维护

更新 WIKI 原始数据后执行：

```bash
python scripts/build_operator_details.py
python -m unittest tests.test_operator_details tests.test_api_server tests.test_frontend_contract -v
```

干员详情是结构化展示数据，不进入 RAG chunk。这样可以避免 Top-K、切片边界和 LLM 总结破坏
表格、图片、音频和 Tab 之间的关系。RAG 仍负责自然语言问答，两条链路相互独立。

## 当前边界

- 媒体仍使用 WIKI/CDN 原始 URL，需要浏览器联网；上游链接失效时页面会加载失败。
- 原始数据中没有内容的 Tab 会显示“该页签暂无公开内容”，不会编造素材。
- 浏览器自动控制插件本轮受本机受信路径配置阻止；已通过 31 名干员数据契约、API 真请求、
  JavaScript 语法和完整单元测试验证。视觉效果仍建议在当前本地页面刷新后人工巡视一次。

## 2026-08-19 媒体与宽屏修订

- 主工作区最大宽度提高到 1720px，档案索引栏缩窄，中等屏幕自动让主内容独占宽度；
- 章节导航增加可拖动的原生横向滚动与蓝黄进度状态条；
- WIKI 图片、技能图标和音频改走白名单 `/api/media` 同源代理，解决浏览器直连 CDN 差异；
- 新增 `intro.imgUrl` 和 `externalVideo` 解析，技能/天赋介绍图与森空岛视频入口不再被静默丢弃；
- 所有 entry 引用按 item ID 关联封面，升级材料和推荐武器以“图片 + 名称 + 数量”展示；
- 表格改为分离式异形数据行：斜切首列、圆角尾部、蓝黄撞色和悬浮位移；每张表格都有独立且常驻的横向进度轨道，支持点击定位、拖动、鼠标滚动与触控滑动同步，未溢出时轨道自动弱化。章节、卡片、页签和表格外框均设置了完整的 `min-width: 0` / `max-width: 100%` 约束链，宽表格只在自身视口内滚动，不再把整张网页撑宽；
- 媒体加载失败时显示明确错误状态，不再只出现无说明的破图。

媒体代理仅允许 `https://bbs.hycdn.cn/image/` 与 `/audio/`，限制响应为图片/音频且单文件不超过
25 MB，避免成为任意 URL 代理。原始 `externalVideo` 只保存森空岛视频 ID，公开视频接口需要
设备签名，因此当前提供来源页面入口，不伪造不可验证的视频流地址。
