# 微信小程序设计

这个目录是网页端的移动入口，复用同一个 FastAPI、配方数据、RAG 和知识图谱，不在小程序里保存模型或 API Key。

## 已有功能

- 配方制造与知识问答使用独立查询词；首次进入均为空；
- 名称联想、本地搜索历史和后端连接状态；
- 可拖动、缩放和折叠的纵向 Canvas 合成树；
- 知识问答、引用来源、检索片段和结构化配方结果；
- 引用表格保持完整 Markdown 块；普通引用角标可点，`干员语音` 来源会回到对应干员；
- 干员档案、富文本表格、图片、语音和外部视频入口；
- KB 的 link、entry 与行内图片保留；WIKI 图片和音频统一走受限媒体代理；
- 与 Web 端统一的终末地黄黑工业档案视觉，并针对小程序触控与主包体积适配。

首页角色立绘与地景图复用 `web/assets/official/` 的已归档官网素材，来源与授权说明见
`web/assets/official/sources.json`；小程序内只保留实际使用的三份副本，便于开发者工具打包。

## 开发者工具运行

先在项目根目录启动单进程后端：

```powershell
$env:WEB_CONCURRENCY = "1"
python scripts/start_server.py
```

然后打开微信开发者工具，选择“导入项目”，项目目录指向本目录。模拟器默认请求
`http://127.0.0.1:8000`，公共配置在 `project.config.json`。

## 真机调试

手机里的 `127.0.0.1` 是手机本身，不能访问电脑后端。调试前：

1. 查询电脑局域网 IP，例如 `192.168.1.20`；
2. 把 `app.js` 的 `apiBase` 临时改成 `http://192.168.1.20:8000`；
3. 确认后端监听 `0.0.0.0`，手机和电脑连接同一网络；
4. 在开发者工具调试阶段关闭合法域名校验，并按需允许 Windows 防火墙端口。

调试后不要把个人机器 IP 提交到仓库。

## 正式发布

小程序正式版只能连接已配置的 HTTPS 服务。发布前应：

1. 部署后端并确认 `/api/health` 返回正常；
2. 把 `app.js` 的 `apiBase` 改成线上 HTTPS 域名；
3. 在微信公众平台配置 request 合法域名；
4. 真机检查名称联想、配方树、RAG 回答、引用、图片和语音；
5. 确认 `.env` 和任何 API Key 都只存在于后端。

`project.private.config.json` 是个人开发者工具设置，已被 `.gitignore` 排除；`project.config.json` 是团队公共配置，继续提交。

## 技术边界与测试

- 小程序仍使用 `wx.request` 整包问答，问答单独使用 180 秒超时，普通接口保持 30 秒；当前未接 SSE，Web 的流式行为不能直接当作小程序能力；
- 配方树使用 Canvas，需独立处理像素比、图片缓存、缩放、拖动、折叠和卸载时的定时器清理；
- Markdown 转换为受控 rich-text，必须覆盖表格、列表和其中的 `[来源N]`；
- Node 模拟测试验证请求与渲染逻辑，不等于开发者工具或真机验收；
- 发布前至少在 Android、iOS 检查长答案、图片/音频、后台切换、弱网、滚动和树手势。

## 扩展准备

- 将 `apiBase` 改为开发、体验和正式环境配置，发布时拒绝 HTTP 与本机地址；
- 请求封装返回可取消任务，页面卸载时同时终止客户端请求；
- 后端实现统一 `RequestContext` 后，对齐小程序超时、取消和错误状态；
- 与 Web 共用纯数据树布局和 `EvidenceRef` schema，各端继续保留平台渲染实现；
- 只有验证目标基础库和代理链路支持稳定分块读取后，再评估流式问答。

测试命令与发布边界见 [TESTING.md](TESTING.md) 和 [DEPLOYMENT.md](DEPLOYMENT.md)。
