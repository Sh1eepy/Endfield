# 使用指南

这份文档写给**使用网页或微信小程序的人**：能问什么、怎么问、界面怎么操作、为什么会答不出来。
想知道它是怎么实现的、怎么部署、怎么改代码，请到 [开发者文档](README.md)。

## 1. 这是什么

一个《明日方舟：终末地》的**非官方**查询工具，回答两类问题：

- **"这个东西怎么做？"** —— 从目标物品顺着配方一路展开到基础资源（清水、矿物、气体矿物、种子）；
- **"这是什么东西？"** —— 从官方 WIKI 的公开条目里检索出有依据的答案，并附上来源。

它和聊天机器人的区别在于：配方、设备、名单这类问题走**确定性查询**，不经过大模型，结果可复现；
只有描述性、解释性的问题才由模型依据检索到的原文组织回答。**证据不足时会直接说答不出来，而不是编一个。**

## 2. 怎么打开

当前**还没有公网部署**，网页与小程序需要在本机运行后端后才能访问：

```powershell
pip install -r requirements.txt
Set-Location web; npm ci; npm run build; Set-Location ..
python scripts/start_server.py
```

看到 `预热完成` 和 `Uvicorn running` 后，浏览器打开 `http://127.0.0.1:8000`。
小程序用微信开发者工具导入 `miniprogram/` 目录，模拟器默认连本机后端，步骤见 [开发指南](DEVELOPMENT.md) 的小程序小节。

> 未配置大模型密钥时，配方树、设备查询、名单枚举和知识库检索仍然可用；描述类问题会退化成返回检索到的原文片段。密钥配置见 `.env.example`。

## 3. 能问什么

| 类型 | 例子 | 返回方式 |
|---|---|---|
| 配方 | `碳块怎么做`、`蓟花怎么获得` | 纵向合成树，最多两个配方，一路展开到基础资源 |
| 设备 | `精炼炉能做什么`、`天有洪炉生产什么` | 设备配方卡与产出清单 |
| 名单/枚举 | `终末地目前有哪些主线任务`、`武陵有哪些干员` | 完整清单，不抽样、不概括 |
| 物品与干员 | `重息壤是什么`、`佩丽卡怎么玩` | 条目正文、干员档案、技能、语音、媒体 |
| 关系 | `诀属于哪个组织`、`武陵的领袖是谁`、`狼卫的妹妹叫什么` | 知识图谱里的明确关系，可追到来源条目 |
| 任务 | `解锁武陵需要做什么任务`、`第二章-进程Ⅶ-谈剑问迹的前置任务` | 前置/后续任务链、参与人物、地点 |
| 描述与剧情 | `佩丽卡是个什么样的人`、`某某角色的性格` | 依据原文片段归纳，附来源 |

**名称有歧义时会让你选**：比如只输入 `花`，系统会返回候选列表，不会替你猜一个。

## 4. 怎么问更容易答对

- **带上具体名字**比泛指好：`重息壤是什么` 优于 `那种通过实验做出来的材料是什么`；
- **一次问一件事**：`武陵的领袖是谁` 优于把五个问题塞进一句；复合问题虽然支持，但更容易只答一半；
- **用游戏里的正式名称**：干员名、物品名、任务名和 WIKI 条目一致时命中率最高，名称联想可以帮主人补全；
- **问"是什么/怎么做/有哪些/谁/哪里"这类明确问法**，比"帮我分析一下"这种开放式要求更容易拿到有依据的答案；
- 枚举类问题**不需要**自己列举，直接问"有哪些"即可。

## 5. 什么时候会答不出来

这些情况会返回"知识库中未找到足够相关的资料来回答这个问题"，这是**设计好的行为**，不是故障：

- 问的东西不在 WIKI 条目里（例如游戏里不存在的物品、还没上线的活动时间）；
- 问法太模糊，检索不到明确相关的片段；
- 涉及的观点在原文明没有证据支持——系统不会替官方设定补全；
- 没有配置大模型密钥时，描述类问题无法生成归纳，只能返回检索片段。

另外注意：**图谱里没有路径，只代表图里没有这条关系，不代表游戏里没有。** 系统遇到这种情况会回退到文本检索，不会下"不存在"的结论。

## 6. 网页界面怎么用

**开场与空间**：每个浏览会话第一次进入会播放约 6 秒的分段开场，可以点「跳过动画」或按 `ESC` 跳过。查询区顶部栏右侧有两个按钮：

- **重播入场**：重新播放开场动画；
- **实时空间 / 静态场景**：切到静态场景会停止实时渲染，查询与结果完全不受影响，适合省电或机器吃力时使用。

系统开启"减少动态效果"时开场会自动简化或跳过。

**查询**：顶部搜索框有**配方合成树**和**知识问答**两个模式。

- 两个模式各自记住自己输入到一半的内容，**切换模式不会自动提交查询**；
- 输入时会出现名称联想，前缀匹配优先；
- 同一个问题在本次会话里问过，会直接复用上次结果；
- 提交后会出现真实阶段提示和等待秒数，**生成过程中可以随时停止**，已生成的内容会保留。

**结果**：

- 提交查询后，档案盒会从阵列中抽出并展开真实结果；等待时可以点「跳过抽取 · 立即阅读」直接看内容；
- 知识回答里的 `[来源N]` 是可点击角标，点开能看到对应的原文片段和条目名；
- 配方树的节点可以点击跳转，支持缩放和展开/收起；
- 宽表格在它自己的容器里横向滚动，不会带动整页；
- 干员档案有章节切换、技能/天赋/潜能标签页、图片、视频入口和多语种语音（点一次播放，再点暂停）。

**反馈**：知识问答的回答下方会问"这个回答有用吗？"，可选「有用」或「没用」。反馈进入人工审核队列，**不会自动修改知识库**。

**空间层**：页面的双螺旋档案阵列、玻璃档案盒和中央环是展示用的视觉层，**不承载任何知识内容**——所有事实都以结果面板里的文字和数据为准。WebGL 不可用时页面会自动静态降级，查询功能完全不受影响。手机上纵向滚动是浏览器原生行为，不会被页面劫持。

## 7. 微信小程序

功能与网页一致，差异在于：

- 目前使用**整包问答**（等待时不逐字显示，而是检索完成后一次给出），单次问答超时 180 秒；
- 配方树是 Canvas 实现，用手指拖动、双指缩放、点击折叠；
- 首页开场被移除，进入即用；
- 支持本地搜索历史。

小程序真机（长答案、图片/音频、弱网、后台切换）尚未完成验收，若在真机上遇到问题，欢迎反馈。

## 8. 常见问题

**答案和游戏里的不一样？**
数据来自官方 WIKI 的公开条目，社区编辑可能有滞后或错漏，发现错误请以游戏内和官方发布为准，并欢迎反馈。

**为什么问同样的东西，配方树只有一个配方？**
每个物品最多展示两个配方（避免树无限膨胀）；如果某个物品有更多配方，说明数据层没有提取到，属于已知边界。

**能导出整篇 WIKI 原文或批量下载吗？**
不能，这是有意的边界。项目只提供检索问答，不提供原文浏览、导出或批量下载接口，也不分发原始抓取副本。

**为什么回答里有的角标点不开？**
结构化的枚举/配方结果直接来自数据库，会标注结构化来源而不是伪造引用角标；只有检索生成的回答才带 `[来源N]`。

**换了个问法就答不出来了？**
检索对用词敏感。先试试换成条目里的正式名称，或用"有哪些/是谁/在哪里"这类明确问法。

**会不会记录我问了什么？**
普通查询只保存**查询指纹**（哈希）和阶段、排名、耗时、用量，不保存原问题文本。只有主人主动点击反馈时，才会连同当时的问题和回答一起保存，并进入待人工审核的隔离区。详见 [接口设计](API.md) 的隐私与数据保留小节。

- 数据来自《明日方舟：终末地》官方 WIKI 的公开条目，界面素材来自游戏官网等公开渠道，均登记了来源与校验值；
- 本项目是**非官方社区工具**，与权利方没有隶属或合作关系，不收费、不含广告，仅供查询与学习交流；
- 游戏名称、图像、文本及其他内容的权利归原权利方所有，查询结果以官方发布为准，不构成官方说明；
- 完整的素材清单、字体许可、数据来源与使用边界见 [素材、数据与免责声明](ASSETS.md)。
